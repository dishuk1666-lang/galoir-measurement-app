# GALOIR WhatsApp Cloud API integration

Status: **deployed but disabled by default**. No customers are messaged until the Meta credentials, templates and Admin activation are complete. Never place WhatsApp tokens in GitHub, config.js, browser code or chat.

## 1. Connect an official WhatsApp Business account

In Meta Business Manager / WhatsApp Manager, set up a WhatsApp Business Platform Cloud API phone number. Collect:
- **Phone Number ID** for the sending number.
- A system-user or permanent access token with `whatsapp_business_messaging` permission.
- Verified access to approved **UTILITY** message templates (business-initiated messages require approval).

## 2. Submit exactly these two Utility templates for Meta approval

Language: **English (en)**. Configure the same language code in the Supabase secret.

**Template name: `galoir_order_confirmed_v1`**

> Hello {{1}}, your GALOIR order is finalised.
> GL Slip: {{2}}
> Bill Number: {{3}}
> Total Amount: INR {{4}}
> Amount Paid: INR {{5}}
> Balance Due: INR {{6}}
> Expected Delivery: {{7}}
> Thank you for shopping with GALOIR.

Template variables, in order: customer name, GL slip, bill number, total, paid, balance, delivery date.

**Template name: `galoir_ready_for_collection_v1`**

> Hello {{1}}, your GALOIR outfit is now READY FOR COLLECTION.
> GL Slip: {{2}}
> Bill Number: {{3}}
> Scheduled Delivery Date: {{4}}
> Please visit our Rajouri Garden store for collection. Thank you.

Template variables, in order: customer name, GL slip, bill number, delivery date.

Important: Meta's approved template structure, language and variable count must exactly match these bodies, or change the corresponding `WA_TEMPLATE_*` settings and function implementation to match. Marketing messages should not use these Utility templates.

## 3. Add secrets on Supabase, not in the app

In Supabase project `ooowmzrfthsozgbcjskm`, navigate to **Edge Functions > Secrets** and configure:

- `WA_ACCESS_TOKEN`: the official WhatsApp Business Cloud API access token.
- `WA_PHONE_NUMBER_ID`: your WhatsApp Cloud API sender's Phone Number ID (numeric, **not** the telephone number).
- `WA_TEMPLATE_CONFIRMED`: `galoir_order_confirmed_v1` (optional: this is the default).
- `WA_TEMPLATE_READY`: `galoir_ready_for_collection_v1` (optional: default).
- `WA_TEMPLATE_LANGUAGE`: `en` (optional: default, must match Meta-approved language).
- `WA_GRAPH_VERSION`: `v25.0` (optional, update to a currently supported Graph API version if needed).

Supabase provides its project URL, publishable and service secrets automatically to Edge Functions. Don't add Supabase secret keys yourself to browser code.

The deployed Edge Function is `galoir-whatsapp-dispatch`. It requires a signed-in active GALOIR staff JWT (`verify_jwt = true`). Staff **cannot** specify arbitrary recipients or messages to send: these are read exclusively from a database outbox generated by restricted database triggers.

## 4. Explicit Admin activation

Log into `https://app.galoir.com` as Admin, open **Capacity Settings > WhatsApp Business Notifications**, then select **Check API Setup**.

When the credentials have been entered and both templates have been approved, check the attestation checkbox and select **Enable WhatsApp Automation**.

The default setting `public.settings.whatsapp_enabled` is **false**. Turning it on does not retroactively send messages for existing billed orders. The database outbox will receive only future events meeting the criteria below.

## 5. Daily cashier / tailoring flow

In **Billing Desk**, enter Total Billing Amount, Amount Paid and the Bill Number. The Balance Due is calculated in the UI, and the database rejects paid amounts greater than the total. Enter **0** if the customer has paid nothing.

**Only tick** "Customer has agreed to receive order updates on WhatsApp" when the customer has actually consented. Consent is recorded with a timestamp on that slip. Without consent, messages are never enqueued.

On the first successful **Confirm Billing**, one order-confirmation notification is queued when Admin has enabled WhatsApp. On the first transition to **Ready** (CRM checkbox, scanner or Tailoring Board), one ready-for-collection notification is queued. Duplicate actions cannot queue another message for that slip/event.

When a logged-in staff member completes these actions or opens the app, it asks the deployed Edge Function to submit queued notifications. The outbox prevents simultaneous sessions from sending the same item. Failed/ambiguous attempts are marked **failed** for manual review rather than blindly resent.

## 6. Understand notification states

- **Pending**: consented event queued, not yet processed.
- **Processing**: claimed by the worker.
- **Submitted**: Meta Cloud API accepted the message request and returned a WhatsApp message ID. This does **not** prove delivery/read.
- **Failed**: needs staff review; check account/template/phone and WhatsApp Manager logs.

The Admin settings page shows the last 60 notifications. Delivery/read receipt webhooks and an always-on scheduled background worker are **not** included in this version; the dispatcher runs from authenticated app activity. A future Cron/Vault worker can provide fully unattended retries without keeping the app open.

## 7. Security / safeguards

- WhatsApp credentials exist only as **Supabase Edge Function secrets**.
- Only **active signed-in staff** can invoke the dispatcher.
- The queue is RLS-protected and authenticated users only have read access.
- Neither a phone number alone nor a saved customer record establishes WhatsApp consent.
- An already-billed slip without recorded consent is not messaged when WhatsApp gets enabled later.
- Payments and other sensitive billing amounts remain hidden from the tailor printout.
- The Admin activation and status checks never send test messages to live customers.
